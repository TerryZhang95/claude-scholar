# Icon and Asset Guidance

Load this module when the figure benefits from icons, imported SVG assets, or lightweight illustrations.

## Why Use Icons

Icons can make structural figures easier to parse by turning abstract labels into quickly recognizable concepts:
- server
- user
- database
- robot
- cloud
- document
- sensor

They are most useful in teaser, overview, comparison, and deployment-context figures. They are less useful in strict IEEE system-model diagrams unless they clarify entity type without weakening technical precision.

## Design Rules

- Keep icons monochrome or two-tone.
- Recolor icons to match the figure palette.
- Use one icon family per figure to keep stroke style consistent.
- Pair every icon with a text label.
- Use larger icons for primary concepts and smaller ones for supporting context.

Recommended size hierarchy:
- primary icons: 40 to 48 px
- secondary icons: 24 to 32 px

## Sources

Useful sources:
- Flaticon
- Noun Project
- Font Awesome
- Tabler Icons
- Heroicons
- Iconfinder
- PhyloPic for organism silhouettes

## Domain Hints

- AI / ML: machine learning, brain, chip, document, retrieval, cloud icons
- robotics: robot, sensor, arm, map icons
- medical / bio: BioRender-style assets, PhyloPic, medical illustration libraries
- wireless / network: network, antenna, cloud, edge, server icons

## Workflow

1. Download only the SVG assets that improve recognition.
2. Normalize them to one palette and one visual family.
3. Keep icon size on a fixed scale.
4. Align icons and labels on the same underlying grid.
5. Export the assembled figure as editable SVG and companion PDF.

## Attribution

If the icon license requires attribution, add a short note in the caption or acknowledgments as appropriate.

## Failure Modes

- mixing multiple icon styles
- leaving icons in their default colors
- relying on icons alone without labels
- turning a technical figure into a marketing slide
